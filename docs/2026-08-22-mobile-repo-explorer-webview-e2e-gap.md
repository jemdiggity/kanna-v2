# Mobile repository explorer WebView E2E gap (2026-08-22)

The repository explorer's native React Native ↔ WebView scroll/message boundary cannot currently be driven by the local Vitest tier: `react-native-webview` is mocked there, and the existing mobile device E2E harness does not expose WebView DOM inspection or synthetic high-velocity scrolling.

The narrower executable coverage runs the generated viewer document in a DOM, verifies a fixed 90-row window for a multi-million-line file, scrolls away and back to prove loitered content cache reuse, and selects a row to verify its absolute line reference. The loiter loader test proves repeated fling viewport messages produce no content request until settling, exactly one settled request, and reuse of an already-loaded range. A separate range-consumer test reconstructs a byte-chunked oversized line.

Closing this gap requires the device E2E harness to add WebView context switching (or a test-only message bridge) with DOM row-count inspection and controllable scroll/fling events. That test should assert the live `.line` count remains at most 90, fling messages do not trigger content reads, settling triggers one read, returning to the range reuses cache, and selecting a visible row emits its absolute `path:line` reference.

The 2026-08-23 line-reference fix additionally needs device coverage that compares the native `WKScrollView` content offset with the fallback line shown in the insert button, taps line numbers to select a single line and range and clear the range, and verifies that a real DOM text selection still takes precedence and can quote its text. Generated-document tests cover the selection rules and label, while a component test proves the native scroll offset is injected into the document; neither narrow test can prove the physical WKWebView reports the same viewport the user sees.

Revision-round-2 coverage adds two lifecycle cases the current device harness also cannot drive deterministically: changing directory/filter/show-all/refresh scope while a native list pagination promise is unresolved, and rerendering the task-detail parent with a fresh equivalent file-reader callback while a WebView remains open. Executable React component tests now defer the directory promise to prove stale rows/cursors are discarded and duplicate pages are suppressed, and rerender the file viewer before scrolling away/back to prove metadata and loitered content remain cached. The generated-document test also proves a long-line continuation appends only after an explicit request, without gaps or duplicate application.

Native verification requires a test-only server delay/future control for browse-list responses plus device-harness hooks that can change explorer controls during that delay, trigger an unrelated task-detail state rerender, and inspect/count authenticated browse requests while driving WebView viewport and continuation messages.
