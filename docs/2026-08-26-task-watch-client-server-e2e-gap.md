# Task watch client/server E2E gap (2026-08-26)

`kanna-cli task watch` is a long-lived process whose important boundary is repeated HTTP long polls plus process-exit notification by an agent harness. The repository does not currently provide an E2E harness that can launch the CLI against a real `kanna-server`, append lifecycle events while the process is blocked, and observe the agent runtime being woken when the child exits. The existing live CLI-contract suite exercises provider processes, not Kanna server task-event fixtures, so adding this there would require a new server/task seeding fixture and a background-process wake assertion.

This task covers the narrower boundaries meanwhile: CLI HTTP fixture tests verify live-tail query construction, cursor forwarding across separate requests, event-time payload passthrough, filtering, actionable exit, follow streaming, and quiet-budget exit; `kanna-server` task-event integration tests continue to cover real database append/wait/cursor behavior and event-time enrichment. A future E2E should start an isolated server, launch the actual CLI binary with an assigned repository scope, append suppressed and actionable events through server-owned lifecycle writes, assert the process remains alive for the former and exits for the latter, and verify a second process resumes from the printed cursor without replay.
