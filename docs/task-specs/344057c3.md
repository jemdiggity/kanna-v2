# Task 344057c3 — Slice-1 billing backend (Stripe + entitlement reducer)

Goal: implement Slice 1 of `docs/specs/accounts-and-billing.md` — the
`services/firebase-functions` billing backend that lets one stranger sign up
and pay on the web. Owner approved starting Slice 1 on 2026-08-20 ("proceed
with the subscription and payments work"). The spec is the contract; this file
records the terms this task works under.

## Scope (in)

1. **Revive function deploys** — `kd cloud deploy --functions` builds and
   deploys the functions package. The "no stray functions" posture is kept:
   `src/index.ts` exports only what this task adds, and the retired
   `createPairingCode` bootstrap stays unexported.
2. **`createCheckoutSession`** (callable) — auth + verified email required;
   refuses while a `comp` grant is active, while an `app_store` source is
   active, and while a Stripe subscription is already active.
3. **`stripeWebhook`** (HTTPS) — signature-verified, idempotent event handling
   (dedupe on `stripeEvents/{event.id}`), out-of-order resolution by the
   event's `created` timestamp.
4. **Source-state + reducer shape from day one** — the Stripe writer writes
   only `users/{uid}/billing/stripe`; `recomputeEntitlement(uid)` reads all
   sources (`stripe` | `app_store` | `comp`) transactionally and derives
   `users/{uid}/entitlements/cloud_access`. Comp beats everything. The reducer
   is **source-complete in shape** — it already honors `app_store` source
   docs — but nothing in this task *writes* an Apple source doc; the Apple
   writers (`appStoreNotifications`, `beginAppStorePurchase`,
   `registerAppStoreTransaction`) are Slice 2.
5. **`firestore.rules`** — stanzas for `users/{uid}/entitlements/{id}`,
   `users/{uid}/billing/{source}` (including `billing/comp`), and
   `appAccountTokens/{token}`: owner-read / no-client-write per Decision 8;
   `appAccountTokens` neither client-readable nor client-writable.
6. **Emulator seed fixtures** for the test matrix.

## Scope (deliberately out)

- Everything in Slices 2–5: `createPortalSession`, `deleteAccount`, the Apple
  functions and JWS verification, relay entitlement enforcement, the web
  account portal, `kd cloud comp grant|revoke|list`, grandfather seeding.
- Live Stripe credentials and any production deploy. No live keys exist yet
  (Slice-0 human item), so verification is emulator + Stripe fixture payloads
  only. Key config arrives via environment/Secret Manager, never committed.
- Mobile and desktop surfaces.

## Constraints

- Verify against the Firebase emulator and Stripe test fixtures/webhook
  payload samples. No live Stripe calls in tests.
- Stripe secrets read from the environment at call time; the repo is public,
  so nothing secret is committed and the functions must degrade to a clear
  configuration error when unset rather than crash at deploy/load time.
- Repo conventions: no `any`, `pnpm exec tsc --noEmit` clean, catch blocks log
  or re-throw, function deploys only through `kd`.

## Done means

- `kd cloud deploy --functions` builds the package and includes `functions` in
  the Firebase deploy scope; without the flag it deploys rules/indexes only, so
  reviving functions stays deliberate (kd tests cover both).
- Emulator rules tests: entitlement docs and every billing source doc
  (`stripe`, `app_store`, `comp`) are owner-readable and client-write-rejected;
  `appAccountTokens` are neither readable nor writable by clients.
- Reducer tests: comp beats stripe; each source alone in each state; two billed
  sources active → `duplicateSources`; revoked never suppresses the other
  source; comp revoked falls back to the paid source; tie-breaks stable.
- Webhook tests against the emulator: duplicate event id → exactly one state
  change; each Stripe subscription state maps to the documented source state;
  out-of-order events do not regress newer state; bad signature rejected.
- Flow test against the emulator: checkout session created → webhook
  `checkout.session.completed` + `customer.subscription.created` →
  `billing/stripe` active → `entitlements/cloud_access` granted.
- `pnpm --filter @kanna/firebase-functions test` and `pnpm test` pass; a dated
  `docs/2026-08-20-billing-e2e-gap.md` note records what Stripe-hosted pages
  keep out of CI (required by Decision 8).

prove, so it is left for the human who lands the Slice-0 Stripe credentials.

## Scope notes

- `firebase.json` gained a `functions.ignore` list so the deploy bundle carries
  `dist/` and the manifest rather than the test suite, the Stripe fixtures and
  the TypeScript sources. This is part of reviving the deploy path, not a
  separate cleanup.
- The functions package moved to `NodeNext` module resolution with explicit
  `.js` import specifiers. Required, not cosmetic: the previous `bundler`
  setting emitted extensionless relative imports that Node's ESM loader cannot
  resolve, so the built entry point failed to load at all.
- Test files in this package now run one at a time (`fileParallelism: false`):
  two suites drive the one shared Firestore emulator and clear it between
  tests, so running them concurrently made each wipe the other's data.
