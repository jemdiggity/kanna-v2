# Task 28dbd45b: diff-aware cloud task publication

## Goal and scope

Make relay reconciliation of the unchanged desktop-to-relay full task snapshot diff-aware. Keep an in-memory, per-connected-publication-session task index seeded from Firestore on connection/reconnection, then write only changed/new task documents and delete only removed/duplicate documents. Preserve convergence after relay restart, reconnect, competing desktop sessions, and task deletion. Keep the desktop protocol and mobile read path unchanged.

## Constraints and completion

- The generation transaction remains the authority that rejects stale publishers; cached state must never let an older session overwrite a newer one.
- Restart/reconnect seeding retains malformed or identity-less persisted task documents so the next authoritative snapshot deletes them. Overlapping websocket handlers serialize their reconciliations per publication session so an older continuation cannot replace newer cached state. (Revision round 1 reviewer feedback, 2026-08-20.)
- Tests exercise the real Firestore-backed relay publication store and prove: warm unchanged snapshots perform zero task collection reads and zero task-document writes; one changed task writes exactly one task document; reconnect/restart converges; removed tasks are deleted.
- Verify with the relay tests and repository `pnpm test` (plus TypeScript checking required by repository conventions).

## Firestore operation count

For `N` tasks and `P` subscribed phones, one steady-state publish changes `C` tasks and removes `D` tasks:

- Before: `N` relay task reads + `N` task writes + about `N × P` listener reads (plus duplicate cleanup queries).
- After warm-up: `0` relay task reads + `C + D` task writes + about `C × P` listener reads for changes (`D` listener removals as applicable). An unchanged snapshot is `0` task reads and `0` task writes.
- Connection/reconnection/restart pays one `N`-document seed read so the first reconciliation converges safely.
