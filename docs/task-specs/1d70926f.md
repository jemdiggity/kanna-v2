# Desktop account portal links

Owner design decision (2026-08-21): the web portal is the sole account-creation and payment surface. Add environment-aware desktop Account preferences links that open `/register` for signed-out users and `/account` for signed-in users in the system browser. The manage action may carry the known email as a non-secret hint, but must not forward authentication tokens; its UI must tell users to sign in with their Kanna account.

Keep mobile sign-in-only in-app and record the unresolved regional external-payment-link entitlement question (US, EU DMA, and Japan) in the accounts-and-billing spec. Do not add embedded signup/payment or an E2E browser-launch test.

Done means component coverage proves both affordances invoke the opener with environment-correct URLs, and the desktop and root test suites pass.

Revision 1 (review feedback, 2026-08-21): when no cloud environment or portal override is set, a packaged non-dev desktop must use the production portal rather than localhost. Preserve local workspace-port behavior in dev and the existing explicit staging, production, and URL-override behavior. Verify with the desktop suite and `./kd test all`; browser-launch E2E coverage remains out of scope because tests stop at the opener boundary.
