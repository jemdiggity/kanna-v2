# Mobile app icon framing

## Goal

Make Kanna's mobile home-screen icon read as a single platform-shaped app icon instead of a smaller rounded icon inside the platform icon mask.

## Scope and constraints

- Correct the source/configuration used to generate the mobile app icon while preserving the existing Kanna artwork and desktop icon.
- Cover the affected mobile platform outputs and keep environment-specific native identity behavior intact.
- Treat this as a native asset/config change: bump every mobile environment's `runtimeVersion` as required by repository policy.
- Do not redesign the logo or change unrelated in-app UI.

## Done when

The mobile icon artwork fills the platform icon canvas without an extra outer inset, configuration/tests document the contract, generated/native output is verified where practical, and relevant mobile type/tests pass.

## Verification

- Expo's iOS prebuild generated a full-bleed 1024×1024 AppIcon from the new source; the generated asset was visually inspected and saved under the gitignored `docs/task-specs/0779ae9c-screenshots/` directory.
- An iPhone 17 Pro simulator install was attempted from the canonical `./kd dev up --mobile` environment. The existing Expo SDK 57 dependency fails to compile under the installed Xcode 26 toolchain before app installation; the gap and narrower coverage are recorded in `docs/2026-09-03-mobile-app-icon-simulator-e2e-gap.md`.
