# Task 48b324bd — Remote dev-server preview architecture spec

**Goal**: produce and commit `docs/specs/remote-dev-preview.md` — an
architecture spec (analysis and design, not implementation) for letting the
mobile app preview a task's dev server, on LAN and remotely through the relay.

**Scope**: the spec must answer the six design questions from the task prompt
(LAN case, remote transport choice, security invariants, UX, capacity against
`docs/specs/relay-scaling.md`, and implementation slices with E2E coverage),
grounded in re-verified source, with every owner decision flagged.

**Constraints**: no product code, tests, or config changes; nothing verified
beyond docs conventions. The committed spec is the entire deliverable.

**Done when**: the spec exists at `docs/specs/remote-dev-preview.md`, is
concrete enough to spawn implementation tasks directly from its slices, and
is committed on this branch.

**Revision round 1** (reviewer feedback, 2026-08-21): the remote session-open
protocol must be internally complete — one authoritative owner per
credential, an explicit success/refusal handshake carrying or binding the
credentials before the phone receives the URL, pending-state cleanup on
timeout/disconnect, no secret exposed beyond the components that require it,
and the P2 boundary plus Layer A/remote E2E requirements extended to cover
credential binding, refusal, timeout/disconnect cleanup, and
wrong-credential rejection.

**Revision round 2** (reviewer feedback, 2026-08-21): resolve the
contradictory remote-open API contract — the REST preview endpoint is
LAN-only (`POST` body drops `transport`), remote sessions are opened
exclusively by `preview_request` + desktop dial-back, and every lifecycle,
DELETE/revocation, UX/controller, and slice reference is updated so no relay
REST descriptor or unresolved alternative remains. Documentation-only; no
E2E coverage required.
