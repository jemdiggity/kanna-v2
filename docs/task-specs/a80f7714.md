# UI visual verification convention

Add a concise binding convention that every mobile or desktop rendered-UI change must be visually verified in the real app before PR creation, including relevant accessibility states, screenshots, inspection, and a PR-description summary; non-rendered tests are not substitutes. Make the general and UI-specialty review agents treat missing described visual verification as blocking, without changing code or widening other agent guidance.

This records the owner directive delivered 2026-08-23: "Keep in mind there are certain classes of issues that agents are poor at evaluating. UI is one of them. Let's test UI changes before making PRs." Done means the canonical instructions and applicable reviewer instructions state the requirement in terse, prose-quality language.
