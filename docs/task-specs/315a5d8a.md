# Task 315a5d8a: terminal recovery lifecycle

## Goal

Prevent worktree development instances from leaving `kanna-terminal-recovery` helpers behind, and prevent a helper whose daemon control channel is gone from busy-looping.

## Scope and constraints

- Trace and preserve the daemon handoff/recovery lifecycle defined in `crates/daemon/SPEC.md`.
- Make `kd dev down` and workspace teardown reap only the recovery helper owned by that exact instance, using recorded process identity or an exact worktree `.build` executable path; never use process-name matching.
- On loss or EOF of the recovery control channel, cleanly exit or wait cheaply according to the helper's intended lifetime.
- Add `kd` coverage proving the target instance is reaped while another instance is untouched, helper-level coverage proving parent/control loss cannot spin, and an E2E test or dated coverage-gap note.
- Do not change production/staging process ownership beyond what is required for safe helper behavior.

## Done when

Both defects are fixed, the required regression coverage passes, Rust is formatted with no new Clippy warnings, and TypeScript checks pass for the touched `kd` code.

## Implemented lifecycle decision

The helper exits when its daemon-owned stdin reaches EOF or fails. It has no independent handoff role: daemon generations recreate it and replay tracked sessions from persisted snapshots, so waiting after loss of the sole control owner would only preserve an unusable orphan.
