### Root causes

1. **Daemon classification/snapshot handoff:** the test treated the successor
   PID file as socket readiness. Startup intentionally publishes that PID just
   before binding the socket, so a loaded successor can be the recorded
   generation while a one-shot `UnixStream::connect` still returns `NotFound`
   or `ConnectionRefused`. Production desktop and server callers already wait
   for the expected PID *and* a successful connection (and then authenticate
   the peer PID), so this is a harness race rather than a product or protocol
   race. The shared test launcher and this test now poll that explicit
   PID-plus-connect readiness boundary, with a documented 30-second guard only
   to contain a wedged child.
2. **Cross-version handoff:** the shared binary launcher made at most 100
   polls at 100ms intervals, then fell through to a PID-only assertion even if
   the socket never became connectable. The cross-version test separately
   imposed a 10-second wall-clock limit on the old process acknowledging and
   exiting.
   Both are eventual handoff events without a 10-second product contract. The
   launcher now returns only after the socket readiness event, and the child
   exit uses the same 30-second hang-containment guard.
3. **MCP activity debounce:** the test's correctness boundary is that a read
   cannot return before the one-second confirmation delay and that the MCP
   response eventually contains the confirmed activity. Its additional
   five-second upper-speed assertion measured cross-process scheduling under
   workspace load, not debounce behavior. The lower bound remains; the MCP
   response is the success event and receives a 30-second hang guard. Related
   server and daemon-event readiness polls now use explicit observed state
   with the same guard instead of fixed 10-second polling budgets.
4. **Server transfer retry:** the first retry backoff is one second, but the
   test scheduled it using SQLite's real `datetime('now')` and then assumed
   later assertions would finish within that second. Under load, the deadline
   could pass before the immediate-not-claimable and positive-delay checks.
   The database operations now have internal variants accepting a SQLite time
   value; production passes `now`, while the test holds time fixed and asserts
   every exact backoff value. This tests retry policy rather than machine
   speed.
5. **`kd` process inventory:** the supplied earlier failure did not reproduce
   in the baseline, isolation, or the 10-run loaded stress probe above. Its
   current synchronization was therefore left unchanged, as required by the
   conditional scope.

No daemon/server protocol or daemon product behavior changed, and no tests
were ignored or serialized.
