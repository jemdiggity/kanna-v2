# Durable ordering for remote-only sidebar repositories

## Goal

Allow local and remote-only repositories to be reordered together in the desktop sidebar, with the mixed order surviving snapshot reloads and a later local import inheriting the remote repository's position.

## Scope and constraints

- Persist remote-only positions by machine-independent repository identity and use persistence—not transient UI state—as the ordering source of truth.
- Make the repo reorder API accurately report identifiers it did not persist.
- Cover mixed local/remote sidebar reordering and unknown server-side identifiers; add cross-boundary E2E coverage or a dated gap note.
- Clean up projected remote repository `sort_order` values so ordering code cannot collapse them all to zero.
- Visually verify the changed desktop UI behavior. No drag-interaction redesign or unrelated sidebar changes are in scope.

## Done when

A remote-only repository can move above local repositories, a local repository can move below it, both positions persist after reload, local import preserves the position, skipped IDs are reported honestly, and relevant automated and visual checks pass.

## Verification

- The desktop E2E reorders a remote-only repository through the real app/server boundary, verifies its `repo_sidebar_order` row, reloads the snapshot, and confirms the rendered order remains.
- Visually inspected `docs/task-specs/706714db-screenshots/remote-repo-reordered.png` (gitignored): the moved remote repository renders first, ahead of both sibling repositories, after reload.
