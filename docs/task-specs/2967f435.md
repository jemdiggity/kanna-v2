# Task 2967f435: Mobile task dev-server preview

## Goal

Let Kanna Mobile open a task's declared, loopback-bound local web dev server when the phone is connected to that desktop over LAN.

## Scope

- Expose claimed task ports in mobile task detail.
- Add an authenticated, short-lived desktop LAN preview session that forwards one declared task port without rebinding the dev server to the LAN.
- Add the mobile Preview affordance and constrained in-app browser, including not-running and retry behavior.
- Cover the server/client wiring and security boundaries with automated tests.

Off-network relay preview, public/shareable URLs, undeclared ports, HTTPS upstreams, response-body rewriting, and Android-specific network configuration are out of scope. The relay design remains the P2 slice in `docs/specs/remote-dev-preview.md` and requires its recorded owner/infrastructure decisions.

## Constraints

- The preview may connect only to `127.0.0.1` at a port already claimed for that task.
- LAN access must use existing paired-device or loopback authentication; preview requests themselves use an independent enter secret followed by an HttpOnly cookie.
- Do not expose or rebind the user's dev server directly to the LAN.
- Mobile changes remain JS-only and do not bump `runtimeVersion`.

## Done

A paired mobile client can discover a task's declared port, open a live HTTP preview through the desktop, refresh/retry it, and receive a clear not-listening state; unauthorized, uncookied, closed-task, and undeclared-port access is refused, and task/session teardown revokes the preview.

## Verification

Automated server tests cover paired authorization, enter-cookie exchange, HTTP and WebSocket forwarding, and revocation. Mobile tests cover LAN routing, URL construction, task-detail propagation, affordance gating, retry, and the constrained WebView. Native simulator/on-device visual verification remains required before review; the dated E2E-gap note records why it was unavailable in this worktree.
