# Mobile terminal keys

## Goal and scope

Add an opt-in Direct input mode for PTY-backed tasks. Normal mode remains the default and preserves the existing logical text composer, quick replies, attachments, queued-input banner, and terminal scroll reports. Direct mode replaces the logical composer with xterm-backed iOS keyboard input and a compact strip that sends `Esc`, arrows, `Tab`, `Enter`, and `Ctrl-C` as exact raw terminal bytes. Do not change SDK/agent-mode task controls or the mobile runtime version (`2.2.3`).

The user explicitly turns Direct mode on or off from the task screen, and it starts off whenever a task opens. The strip must be disabled with a visible reason unless a non-legacy paired connection advertises `term_input_boundary` and has an attached terminal subscription for the task.

## Terminal input contract

- `Enter` (`\r`) is a submission boundary: it submits the highlighted TUI choice or an empty composer.
- Arrows (`ESC [ A/B/D/C`) are controls: menu navigation neither declares a draft nor submits one.
- `Tab` (`\t`), `Esc` (`ESC`), and `Ctrl-C` (`ETX`) are drafts because their effect is context-dependent: Tab can accept a Claude suggestion into the composer, while Esc/Ctrl-C can clear an existing draft. Declaring them as controls could leave accepted text unattested; declaring them as submission would incorrectly release queued logical input even when they did not submit.
- No new daemon frame kind is needed. The daemon already resolves a declared draft from a newer rendered empty composer (`SessionHandle::attest_empty_composer`), so Esc/Ctrl-C clearing a draft cannot permanently strand later logical messages. Until rendered emptiness is proven, holding those messages is the safe result.
- Direct-mode typing is encoded by the existing xterm instance rather than reconstructed from React Native text changes. Exact Return is a submission, exact cursor-key sequences are controls, and other text, paste, Backspace, and escape sequences are drafts. Turning Direct mode off blurs xterm and restores the unchanged logical composer.

## Done when

Direct mode is off by default, can be turned on and off, exposes the iOS keyboard plus special-key strip, and sends xterm-encoded bytes with the correct frame kinds. The exact bytes and kinds reach LAN/relay terminal input, unavailable states explain why input is disabled, unit and navigation integration tests cover mapping/gating and Esc/Enter framing, and remote E2E coverage proves desktop-side PTY delivery without an appended Enter. The mobile TypeScript checks and tests pass. Simulator and owner on-device verification must demonstrate direct typing plus menu dismissal/navigation/selection, with screenshots saved under the gitignored `docs/task-specs/33213414-screenshots/`.
