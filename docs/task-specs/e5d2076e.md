Owner directive (2026-08-22): establish authenticated, deliverable sending for Firebase Auth verification, password-reset, and email-change messages, replacing the stock `noreply@<project>.firebaseapp.com` sender. The staging failure to `kanna.staging@tampopomyoko.com` (Microsoft 365; no inbox or junk delivery) is the motivating incident.

- Implement the chosen path end to end for `kanna-staging`, keeping the portal's client-side Firebase Auth flow unchanged where practical. Store credentials only in Secret Manager/Firebase parameters, following the billing configuration pattern.
- Specify exact DNS/provider/Firebase changes and surface owner-only work (provider signup/payment, registrar changes, inbox access) as blockers. Do not alter production without a named human request.
- Add a production replication runbook and a dated E2E-gap note because real-inbox delivery cannot be automated in CI.

## Decision and implementation record

Chosen: Firebase's Google-managed custom-domain Auth sender on the dedicated `auth-staging.kanna.build` subdomain. It preserves the portal's `sendEmailVerification` flow, requires no function or secret, is DMARC-alignable, and adds no provider cost at 10k users. Custom SMTP is deferred until Kanna has non-Auth transactional mail; a fully custom OOB-link function is rejected as needless security and lifecycle surface. The comparison and production runbook are in `docs/ops/account-email.md`.

Staging was changed on 2026-08-22: Firebase has the applied custom domain `auth-staging.kanna.build` with `useCustomDomain: true`, and all three account-email templates use sender local-part `accounts`, display name `Kanna`, and reply-to `support@tampopomyoko.com`. `method` remains `DEFAULT`; no production configuration was touched.

### DNS and Firebase evidence (2026-08-22)

The owner added the five GoDaddy records listed in `docs/ops/account-email.md`. The first documented DKIM targets were wrong: Firebase doubles an existing hyphen while replacing dots with single hyphens, so the correct target begins `mail-auth--staging-kanna-build`, not `mail-auth-staging-kanna-build`. The single-dash records caused `DKIM_MISMATCH`; after correction, verification succeeded and the manager ran `APPLY`. Live DNS returns both corrected targets, and live Firebase readback reports `customDomain: auth-staging.kanna.build`, `useCustomDomain: true`, and `method: DEFAULT`.
