# LAN mobile notification delivery

## Goal

Deliver `kanna_notify_mobile` notifications over each live authenticated mobile LAN/KSP connection, with the existing cloud push path as fallback, so an actively connected phone can notify the user without cloud signup or a push token.

## Scope and constraints

- Add a notification message to the existing server/mobile stream; do not add a socket or change relay/cloud services.
- On mobile, surface a received LAN notification with a foreground in-app banner and haptic, or a local Expo notification while backgrounded.
- Add backward-compatible per-channel response accounting, including `lanDeliveredCount`, and report no devices only when neither LAN nor push has a recipient.
- Prevent a push-registered, LAN-connected device from buzzing twice by preferring successful LAN delivery and invoking push only when no LAN device accepts the notification; document the rule and that iOS LAN delivery works only while the app/socket remains alive (foreground or background grace period).
- Extend the real-server/mobile-transport LAN E2E to prove delivery reaches the client callback. Update narrower tests and public boundary documentation as needed.

## Done when

The server broadcasts a requested notification to live mobile LAN clients, the mobile client surfaces it according to app state without duplicate buzzes, result accounting covers both channels, and the LAN E2E passes. The current simulator limitation and narrower verification are recorded in `docs/2026-08-23-lan-mobile-notification-visual-e2e-gap.md`.
