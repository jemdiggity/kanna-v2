# Open mobile cloud signup

Owner directive (2026-08-24): “the profile page says cloud access is invite only. Let's open it up.”

Scope widened by the owner on 2026-08-24: “We have payments set up, so let's just open it ALL.” This replaces the earlier mobile-only surface scope with a repository-wide removal of invite-only gating and copy. Signup, verified email, and subscription are now the ordinary cloud-access path on every surface; comp grants remain the exception.

## Goal and scope

- Remove the mobile Account sheet's invite-only/request-access messaging and add Firebase email/password account creation with a verification email.
- Keep signed-up, unverified users in a clear verification state that refreshes until verified.
- Tell verified users without cloud entitlement that a subscription is required and link them to the portal subscribe page.
- Check functions and relay for invite/allowlist enforcement; remove it only if it gates ordinary signup. Preserve comp access and grandfathered invitees unchanged.
- Sweep mobile, desktop, web portal, services, and documentation for invite-only gating or stale claims and align them with the open signup → verification → subscription flow.
- Replace the invite-only component test with signup-flow coverage and visually verify signed-out, unverified, verified-unsubscribed, and entitled states in the iOS Simulator.

## Constraints and done

Subscription purchase remains on the portal; do not add mobile IAP. Do not touch production Stripe configuration or block on it; production Stripe setup is the owner's upcoming step and staging keys remain in place. This is expected to be JS-only, so do not bump `runtimeVersion`. Work is done when all invite-only surfaces are removed, the four mobile account states behave as above, relevant tests and TypeScript checks pass, and screenshots are captured and inspected. The external subscription link may need reconsideration before production App Store review.
