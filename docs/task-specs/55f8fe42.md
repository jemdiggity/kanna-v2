# Remote terminal focus on selection

## Goal

Make an available, unblocked remote desktop terminal receive keyboard focus when it becomes the active task, matching the existing local-terminal behavior.

## Scope and constraints

- Desktop app only; no daemon, server, or mobile changes.
- Share the guarded focus-on-active behavior between local and remote terminal views: wait for Vue layout, restore native webview focus, then focus on the next animation frame (or a bounded fallback when frames are suspended) unless a modal overlay is open.
- Preserve user-intent exclusions: do not focus a blocked remote task, a remote placeholder without `cloudTerminalRef`, an open ShellModal, an active rename editor, or the focused sidebar search/filter input.
- Keep `CloudTerminalCache`'s `v-show`/`active` lifecycle; do not replace it with KeepAlive.

## Done when

- A component test proves `CloudTerminalView` focuses when `active` changes to true and does not focus through a modal overlay; shared behavior has focused unit coverage where useful.
- A desktop E2E clicks local and remote task rows in the sidebar and proves each active terminal's xterm helper textarea receives DOM focus.
- `pnpm exec tsc --noEmit` and `./kd test all` pass.
- The real desktop flow is visually checked with local and remote tasks where the available LAN/relay pairing permits it, with the result recorded here and screenshots kept in the gitignored task screenshot directory.
