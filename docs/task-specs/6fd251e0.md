# Remove completion notifications from task input

## Goal

Stop `kanna-server` from injecting `TASK <child-id> DONE [success|failure|closed]: <title>` into a manager task's PTY. Managers observe child completion through `kanna_wait_events`, `kanna_wait_task`, and existing durable run/task events.

## Scope

- Remove completion-notification PTY delivery and the resulting `task_input` rows while preserving all other daemon-exit effects and the exact `success | failure | closed` completion vocabulary on existing structured surfaces.
- Retire the now-vestigial `notify_task_id` creation parameter and `kanna_set_task_notify` surface coherently across the server, shared tool catalog, CLI, and MCP. Preserve legacy database columns/data only where schema/snapshot compatibility requires them; remove active claiming and routing logic.
- Update agent instructions and current architecture/product documentation to describe MCP wait-based completion observation.
- Replace completion-injection integration/E2E coverage with coverage proving no PTY/input-ledger delivery occurs and completion remains observable through the existing event feed with the exact status.
- Do not introduce a replacement delivery mechanism, event type, or input source/label.

## Constraints and completion

Existing historical `task_input` rows remain readable. The work is done when registration is no longer accepted or advertised, completion does not write to a notify target even for legacy rows, status-bearing durable events/results remain intact, parity tests pass, and cross-boundary coverage is updated or a dated gap is documented.
