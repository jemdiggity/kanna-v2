The resolved `expo-image-manipulator` 57.0.11 / Expo 57.0.6 / `expo-modules-core` 57.0.5 set was introduced while adding the photo picker and downscaling modules.

Toolchain finding: Expo SDK 57 requires Xcode 26.4 (Swift 6.3), as confirmed by an [Expo maintainer on the source-build report](https://github.com/expo/expo/issues/47539). The failed builds invoked `/Applications/Xcode.app` directly with no `DEVELOPER_DIR` or alternate-toolchain setting, and their captured compiler command referenced `iPhoneOS26.2.sdk`; the same application path now reports Xcode 26.6, so Xcode was upgraded in place rather than pinned by `kd`. The latest published SDK 57 releases are already Core 57.0.12 and JSI 57.0.5. The JSI annotation came from Expo [PR #49120](https://github.com/expo/expo/pull/49120) for Xcode 27 and was not an upstream fix that could honestly be described as a backport. In accordance with the Owner directive, all attempted Xcode 26.2 compatibility patches and the forced source-build configuration were eliminated rather than retained as permanent forks. Physical verification must use the aligned packages unpatched under the selected Xcode 26.6.

Done means the committed dependency graph is Expo-SDK-compatible and guarded against regression, all three runtime versions reflect the new native boundary, automated checks pass, and Dev plus Staging have device-console evidence of surviving native startup (or any genuine external verification blocker is explicitly reported).
