## Failure inventory, root causes, and fixes

- `cloud-pairing-auth-discovery.e2e.test.ts` — `stops reporting the account's machines once the phone signs out` expected a signed-in mobile auth session but received `{ status: "error", user: null }`. Firebase accepted Buffy's credentials and returned a token; the harness adapter then lacked the newer `MobileAuthSdk.reloadUser` and `getCloudAccess` methods, so post-sign-in account loading threw and was reported as a sign-in error. Complete the test adapter with reload/cloud-access behavior (and the required, deliberately unsupported account-creation method).
- `terminal-flow.e2e.test.ts` — `keeps a partial raw draft separate from a simultaneous logical task message` and `keeps a queued logical message behind a multiline bracketed-paste continuation` expected the held input request to reject. The current contract accepts the durable queue entry with HTTP 202 and `{ status: "queued", reason: "input_held_by_draft", queuedInputCount: 1 }`; both tests already proved that the message remained isolated and was released after the terminal submitted. Assert the structured queued response instead of the retired rejection.
- `lan-layer.e2e.test.ts` — `keeps a LAN terminal draft separate from a simultaneous logical task message` carried the same retired rejected-promise assertion through the LAN transport. Assert the same resolved structured queue result; retain the scenario's proof that neither message is submitted or concatenated before the human submission boundary.
- `task-listing-actions.e2e.test.ts` — `discovers closed children and parent-scoped events through a real CLI and server` hard-coded the old stateless `p3.` cursor even though both agent-facing CLI paths now request the documented process-local short cursor. Assert the current bounded `kh1.` handle shape while retaining the resume checks.
- `task-listing-actions.e2e.test.ts` — `advances stages, completes stages, requests revision, runs merge agent, and closes with current durable-task semantics` omitted `runId` from a directly constructed request-revision HTTP payload. Spawned review runs are completion-bound, so the server correctly refused an unbound agent verdict. Read the review stage's durable run and send its id, as this same test already does for complete-stage verdicts.
- Standalone TypeScript — the same incomplete `MobileAuthSdk` adapter caused one diagnostic listing `createUserWithEmailPassword`, `reloadUser`, and `getCloudAccess`; two staging fixture objects failed the repository's `NodeJS.ProcessEnv` shape because they omitted required `NODE_ENV`. Complete the adapter and make both fixtures explicit test environments.
