# Mobile task-worktree file explorer

## Goal

Add a read-only mobile file explorer for a task's current worktree, backed by `kanna-server` over the existing LAN and relay transports.

## Scope and constraints

- Add viewport-sized, paged directory-listing and line-range file-reading operations scoped only to the task's current worktree.
- Canonicalize the browse root and every requested path, reject traversal and symlink escapes, detect binary content, and expose no mutation, download, git, or search-in-files operations.
- Add mobile directory navigation with breadcrumb/back, refresh, name filtering, and a read-only text viewer with line numbers and horizontal scrolling. File lines render as metadata-sized skeletons during fast scrolling; real line ranges load only after the viewport loiters, are cached, and receive extension-based syntax highlighting that works on partial ranges. Binary/image content may use a non-preview stub.
- Allow text selection/copy and an action that inserts the selected file path plus line number/range into the task composer, optionally including the selected text as a quoted snippet. Copying a link to a line is a possible follow-up, not part of this task.
- Route LAN and relay requests through existing request machinery, entitlement rules, and a dedicated file-browse relay byte-odometer traffic class.
- Keep the mobile change JavaScript-only; do not change `runtimeVersion`.
- Browsing is a task-detail function on the task's owning machine; there is no repository-level or cross-machine selection surface. LAN and relay use the same per-request caps.

## Done when

Server security/directory paging/line-range caps/binary tests, mobile navigation/filter tests, skeleton/loiter cache tests (including no content fetch during flinging), composer-insert tests, and a real-server LAN boundary test cover the feature. The requested repository checks pass or any unrelated/pre-existing failures are reported.
