# Relay stats-secret deploy diagnostics

## Goal

Make `kd cloud deploy` distinguish an unset relay stats token from VM Secret Manager permission denial and other fetch failures, while keeping the optional dashboard non-fatal.

## Scope and constraints

- Update the VM-side relay deploy script around `kanna-relay-stats-token` and its tests.
- Name the VM service account in the 403/permission diagnostic, and include the HTTP status for other fetch failures.
- Inspect the client-side deploy preflight and add only a best-effort warning if it can cheaply detect the missing IAM grant; do not require new operator permissions.
- Do not change the required relay secret behavior or make the stats dashboard mandatory.

## Done when

The deploy script emits distinct notes for empty/missing payload, permission denial, and other fetch failure; focused deploy tests cover the generated script and any preflight behavior; TypeScript checks pass.
