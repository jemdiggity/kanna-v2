# Task e463bb8a: idle sessions shown as working

## Goal

Make daemon-derived task activity converge to idle/unread after a PTY agent finishes, without cosmetic provider TUI redraws (especially Codex spinner, status-line, and update-banner chrome) repeatedly marking the task busy.

## Scope and constraints

- Trace and fix the existing daemon terminal-state → kanna-server activity pipeline, building on positive Waiting/idle detection and the server activity-event debounce from PR #1164.
- ANSI terminal control bytes must not themselves count as meaningful work; use a real parked-Codex capture as a regression fixture.
- Cover the desktop sidebar path when `runtime_status` is null. Avoid UI changes if the server-owned activity value already supplies the correct fallback.
- Add server-level recorded-output coverage and a real-daemon integration test proving convergence within the configured window.
- Do not add polling/retry mechanisms or change unrelated task/read-state semantics.

## Done when

Parked sessions remain non-working through idle-chrome repaints, active sessions still become working, null runtime status renders safely in the sidebar, and `cargo test -p kanna-server` plus `./kd test all` pass (or an environment-only failure is documented).
