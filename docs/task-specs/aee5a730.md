# Task aee5a730

## Goal

Remove Kanna's current dedicated PR review UI from desktop and mobile after the
owner directive from task f1c3ca89: “we should remove the PR review UI now.”
This directive was delivered to this implementation task on 2026-09-05 by the
owner via that originating task.

## Scope

- Remove the desktop diff viewer's dedicated PR review surface: line-level
  annotations, comment composer/drawer, request-changes composer/action,
  approval/verdict bar, review-only shortcuts, comment/head persistence, and
  tear-off/review plumbing. The mobile task action menu has no dedicated PR
  review controls to remove; keep its existing general actions.
- Preserve general task diff/file viewers, PR links, ordinary workflow stage
  advancement on desktop/mobile, the PR-stage approve post, and merge backend
  behavior.
- Update affected product documentation/tests so removed controls do not leave
  dead actions or shortcuts.
- Clean up the removal sweep's stale references in
  `docs/specs/qa-dispatch-review.md`, `docs/kanna-server-boundary.md`,
  `crates/kanna-server/src/task_creator/stages.rs`,
  `docs/2026-08-07-merge-handoff-close-backstop-e2e-gap.md`, and
  `docs/2026-07-08-setup-agent-live-e2e-gap.md`.
- Do not implement the replacement review experience being designed in task
  231ad8fc.

## Done when

The dedicated review surface is unreachable and its obsolete actions/shortcuts
are gone, while generic viewers and stage advancement/approve-post semantics
remain covered by relevant checks. Changes stay bounded to this removal.

## Verification

The real app was launched with `./kd dev up`, and the mock E2E app was also run
for the diff-view coverage. On a task at the `pr` stage, opening the diff modal
with ⌘D rendered the general diff viewer with no verdict bar, comment drawer, or
review composer; the toolbar, content, and search-bar layout remained intact
after removing `position: relative`. In the ⌘/ shortcuts list for the `diff`
context, the four removed entries — Toggle Comments, Submit Comment, Request
Changes, and Approve — were absent and no other entry regressed; ⌘S remained
listed in the main context. No accessibility variant applied because this
change added no animation, gesture, or dynamic layout.
