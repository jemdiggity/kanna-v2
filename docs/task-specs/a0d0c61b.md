# Mobile task IDs

## Goal

Generate client-supplied mobile task IDs in the conventional eight-character lowercase hexadecimal shape while preserving durable create/retry idempotency.

## Scope and constraints

- Change only the mobile task-ID generator and its tests; this is a JS-only mobile change, so do not bump `runtimeVersion`.
- Keep the server accepting 8–64 lowercase hexadecimal client IDs until old deployed mobile versions no longer need 64-hex compatibility, and document that compatibility boundary in code/tests.
- Do not migrate existing long-ID tasks or change their lookup, branch, worktree, or transcript behavior.
- Display hardening for existing long IDs belongs to task `6de66e07` and is out of scope.

## Done when

Mobile tests prove newly generated IDs are eight lowercase hex characters and recovery reuses the frozen ID, while server tests prove an eight-character requested ID round-trips and retain 64-character acceptance as an old-client compatibility fence.

## Revision 1

Reviewer feedback delivered 2026-08-22 requires the mobile app-model boundary tests to recognize and assert the new eight-character ID shape in cloud fallback transport and durable task-creation persistence/retry coverage. No new E2E test is required; the existing controller recovery, app-model boundary, and server route tests cover the format change end to end across the relevant boundaries.
