# Mobile terminal AppState grace period

## Goal

Keep the currently attached mobile terminal visually uninterrupted across brief iOS interruptions such as opening and dismissing the app switcher, while retaining bounded background resource use and the existing reconnect behavior after a real or failed disconnection.

## Scope and constraints

- Treat iOS `inactive` separately from `background`: inactive-to-active must preserve the live attachment, terminal buffer, and UI with no reconnect chrome.
- On real backgrounding, pause visible terminal consumption and retain the transport for a 20-second grace period. Resume it without a reconnect when the app returns in time; after the grace expires, close it and reconnect through the existing snapshot/resume path on foreground.
- If the OS or network kills the retained transport, use the existing reconnect behavior. Do not change native code, Expo/native configuration, or `runtimeVersion`.
- Add mobile tests for quick inactive return, return within background grace, background grace expiry, and the unchanged reconnect path. Document the physical-device switcher-gesture E2E gap if it cannot be automated reliably.

## Done when

The AppState transition matrix is covered, brief interruptions do not clear or reload terminal output, background bytes are not applied to the visible terminal until foregrounded, expired/dead connections reconnect as before, TypeScript checks pass, and no native runtime-version bump is needed.
