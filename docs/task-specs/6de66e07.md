# Mobile task-card title for arbitrary IDs

## Goal

Ensure the mobile Tasks tab renders the server-provided title for tasks with any ID shape the server accepts, including common mobile-created 64-hex IDs, and uses a humane prompt excerpt rather than a raw ID when a title is missing.

## Scope and constraints

- Trace the real server-to-mobile listing path and fix any boundary that drops the title or mishandles an accepted ID shape.
- Add mobile component coverage for a 64-hex-ID task with a title and for the missing-title fallback, plus coverage at any faulty serialization boundary.
- Do not change ID generation, migrate, or rewrite task IDs; ID-generation work is a separate task. Keep the change JS-only if practical; do not bump the mobile runtime version for JS-only work.
- Add a dated E2E gap note if a real `kanna-server` E2E is not practical.

## Directive history

- Manager correction, 2026-08-22: 64-hex IDs are not legacy artifacts. All mobile-created tasks currently use them because the create API accepts client-supplied 8–64 hex IDs and mobile generates 64-hex values. Treat them as a common current shape; keep this task scoped to display robustness because the generator fix has its own task.

## Done when

The stored title survives the listing path and renders on the card for arbitrary string task IDs, missing titles fall back to a prompt excerpt and never the raw ID, and focused tests plus TypeScript checks pass.
