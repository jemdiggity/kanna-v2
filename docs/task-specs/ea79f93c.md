# Account deletion

## Goal

Ship an in-app and web-portal account deletion flow satisfying Apple App Store Review Guideline 5.1.1(v), backed by one authenticated, retryable `deleteAccount` callable that performs real cloud deletion.

## Scope and constraints

- Cancel active Stripe subscriptions immediately without refunds, then delete every Firestore document keyed by the Firebase uid (including billing, entitlement, published task/desktop mirrors, and relay pairing records), and delete the Firebase Auth user last.
- Make partial failure retryable and the whole operation idempotent. Complimentary access is deleted and is not restored if the same person signs up again.
- Fence cached and in-flight relay publishers with durable deletion state outside `users/{uid}` so no desktop/task mirror can be recreated once deletion starts; keep Firebase Auth deletion last.
- Add hard, loss-specific confirmation in mobile settings/account UI and the web portal account page; call the shared backend and sign out locally after success.
- Ensure deleted-account desktops become clearly signed out after relay credential refresh while LAN and QR-paired local functionality remain unchanged.
- Extend `docs/specs/accounts-and-billing.md` with ordering, idempotency, survival/re-signup semantics, cancel-at-once/no-refund/no-undo policy, Apple guideline citation, and data export as a follow-up.
- Keep the mobile change JS-only. Apple IAP, data export implementation, grace/undo windows, and refund logic are out of scope.

## Done when

Functions tests with mocked Stripe cover the ordered full flow plus failure and rerun; Firebase-emulator/relay integration covers an already-authorized publisher at cached and in-flight deletion boundaries and proves its mirror stays absent; portal and mobile tests cover confirmation through authenticated callable deletion and local sign-out, or a dated E2E gap note precisely records a surface that the current harness cannot drive; desktop signed-out degradation is verified; and the requested functions, relay, portal/mobile, root, and `./kd test all` checks pass (or any environment-only limitation is reported).

## Revision directive

Reviewer feedback delivered 2026-08-21 requires the durable Functions↔Firestore↔relay publication fence above and cross-boundary callable coverage (or a dated, surface-specific E2E gap note where the current harness cannot drive it), while retaining ordered failure/rerun coverage.

Revision round 2 feedback delivered 2026-08-21 expands that durable fence to
every user-reachable writer: Firestore Rules must reject cached owner-token
writes to `users/{uid}` and `desktopCredentials/{desktopId}`, and
`createCheckoutSession` must reject a tombstoned uid before Stripe or
Firestore side effects. Emulator coverage must prove pre-tombstone client
writes are removed, post-tombstone writes are denied, and checkout creates no
Stripe or Firestore state. The portal system test must also reliably await the
UI-triggered callable through Auth deletion and local sign-out, including a
cold Functions emulator start, and clean up its mounted UI.

Revision round 3 feedback delivered 2026-08-21 requires atomic, durable
coordination between checkout and deletion rather than a one-time tombstone
preflight. An admitted checkout must either keep deletion retryable while it
is creating Stripe state or abort and clean that state up; deletion must fence
and expire every recorded open checkout before it can succeed. Emulator
coverage must pause Stripe after admission, interleave deletion adversarially,
and prove that the eventual successful deletion leaves no uid-owned data,
billing reverse map, or usable checkout session.
