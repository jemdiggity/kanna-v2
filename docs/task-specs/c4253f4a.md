## Resolution and manual boundary

The history is two failures across two advertisement implementations. Before 2026-08-21, macOS used `mdns_sd` raw multicast sockets; simultaneous Kanna processes competed for multicast packets, explaining the remembered dev failure while staging could previously work. The 2026-08-21 fix moved macOS to system `DNSServiceRegister`, which made the packaged app's declared Bonjour types authoritative. Unified `mDNSResponder` logs from the installed, signed staging process identify PID 84398 and explicitly say `App Info.plist(NSBonjourServices) does not allow '_kanna-mobile._tcp' for (build.kanna.staging)`. There is no evidence that a recent OS update introduced this behavior: macOS 26.2 was installed on 2026-02-12, while Kanna changed advertisement APIs on 2026-08-21. Bare dev PID 86941, launched by `kd` in its detached development context, registered port 48153 successfully on the same macOS 26.2 host and needs no bundled plist; the packaged app does.

New sessions now emit the 58-character, alphanumeric-mode-pure `KANNA1:<DESKTOP-ID-UPPERCASED>:<CODE>` payload instead of 119-byte JSON, reducing the observed QR from version 7 (45×45 modules) to version 3 (29×29) at error correction M. Mobile remains compatible with legacy version-one JSON and treats the UUID-derived desktop identity case-insensitively. The desktop renders a 370px source image at 185 CSS pixels instead of 120, and the QR decoded exactly both standalone at 370/185px and from the real desktop screenshot. That decoded string parsed through the mobile implementation and completed a real claim against the advertised bare dev endpoint. Simulator verification covers scanner-ready, in-flight, visible failure, and successful pairing states; the owner's physical iPhone 15 scan against rebuilt staging and current bare dev remains required before merge.

The canonical Kanna Task Environment preamble shared by every default agent now directs agent-created temporary artifacts to `.tmp/` at the active worktree root, while preserving application-, framework-, and OS-managed temporary paths. The worktree-root `.tmp/` is gitignored, and both the TypeScript prompt builder and Rust task launcher tests assert the delivered instruction.
