# Mobile custom relay endpoint

## Goal

Let signed-in mobile users use an authenticated, self-hosted Kanna relay without a Kanna Cloud subscription by setting a persistent custom `wss://` relay endpoint.

## Scope

- Add validated mobile settings for a custom relay URL, show when it is active, and allow resetting to the environment default.
- Apply endpoint changes immediately by cleanly replacing relay-backed connections and subscriptions.
- Preserve Firebase authentication and the hosted-relay entitlement policy; document the self-hosted authentication and setup flow.
- Add unit coverage for validation and resolution precedence plus mobile-to-relay boundary coverage, or a dated E2E gap note if the current harness cannot express it.
- Visually verify the settings UI in the iOS simulator and retain gitignored screenshots for the task record.

Desktop UI, hosted-relay policy changes, and native/Expo/plugin changes are out of scope. This must remain JS-only and retain mobile runtime version `2.2.2`.

## Done

The override persists across launches, is used by relay connect/reconnect immediately after a change, self-hosted relay auth works for a signed-in non-subscriber without weakening hosted service checks, documentation and tests are updated, TypeScript checks pass, and the changed UI has simulator screenshot evidence.

## Implementation record

The relay authenticates the phone's Firebase ID token and the desktop's hashed credential against the same Firebase project and uid. Subscription gating is a separate, opt-in relay setting that remains off for self-hosting; no hosted policy or authentication check changed. Operators must have Firebase Admin access to the Firebase project used by their Kanna app build—customizing the URL does not make an unrelated Firebase project compatible.

The UI was visually exercised on an iPhone 17 Pro simulator on 2026-09-03. The default card, custom indicator and reset control rendered correctly, changing endpoints replaced the live client, and reset returned to the environment endpoint. Inspected screenshots are retained under the gitignored `docs/task-specs/e07f465a-screenshots/` directory.
