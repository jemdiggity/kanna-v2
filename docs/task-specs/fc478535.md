# Mobile repo explorer swipe polish

## Goal

Make repo explorer edge-swipe navigation work across the entire explorer screen and visually match native iOS navigation by revealing the incoming history view beneath the outgoing view during an interruptible, spring-settled transition.

## Scope and constraints

- Move gesture hit-testing to the screen container while preserving the existing edge zones and avoiding interference with vertical scrolling, pull-to-refresh, and WebView horizontal panning.
- Render both outgoing and incoming directory/file views during back and forward drags; mirror the transition direction and restore both views on cancellation.
- Add a component regression test for swiping through blank space below a short directory list, and keep or extend history-stack coverage.
- Treat animation feel as manual verification and report what was test-verified versus what still needs on-device verification.
- This is a JavaScript-only mobile change. Do not change `runtimeVersion`.

## Done when

Edge swipes can begin anywhere within the allowed edge zones across list rows, list blank space, and the file viewer; completed and cancelled gestures preserve correct history state; automated tests pass; and the transition implementation provides the native-style incoming-view reveal and spring settlement requested in owner feedback dated 2026-08-23.
