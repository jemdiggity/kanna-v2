# Remote desktop task file views

## Goal

Make the desktop tree explorer, file preview, and diff view read from the owning machine for non-local tasks, so a remote task never manufactures a path under the viewer's local checkout or appears to have zero files.

## Scope and constraints

- Owner clarification delivered 2026-09-03: the motivating Studio task's `0 files` result was truthful because its worktree was created from an empty HEAD (tracked separately as task `47b7cb85`). Do not use that incident as this task's reproduction or claim that it should have contained files. Reproduce with any machine-B-owned task viewed from machine A.
- Route remote directory reads through the existing relay-authenticated, task-worktree-scoped `GET /v1/tasks/{task_id}/browse` API, remote file content through `GET /v1/tasks/{task_id}/files/content`, and remote diffs through `GET /v1/tasks/{task_id}/diff`. The existing `/browse` surface already supplies the directory-listing API requested by this task; keep mobile consumers unchanged and make only additive client changes.
- Reviewer feedback delivered 2026-09-03 (revision 1): preserve whether the authoritative owner route is LAN or cloud, including across tree/diff tear-off windows. LAN-owned tree, file, and diff reads must use the authenticated transfer sidecar and must not instantiate the relay client.
- Reviewer feedback delivered 2026-09-03 (revision 1): preserve the server's `truncated` diff result and show an unmistakable warning above the available partial patch when the 1 MiB response cap is reached.
- Preserve local filesystem/git behavior for locally owned tasks, but render an explicit unavailable/error state when a local or remote worktree cannot be read. Remove the tree explorer's repo-root fallback and any empty-tree result caused by an access failure.
- Cover owner-routed remote tree/file/diff requests and explicit error rendering. Add a dated E2E gap note if the desktop cross-machine harness cannot exercise the relay path end to end.
- Visually verify the changed desktop states with `./kd dev up`, saving uncommitted screenshots under `docs/task-specs/430270e2-screenshots/`.
- The separately filed `git_ahead_behind` base-ref fallback bug is out of scope.

## Done when

A remote task's explorer, preview, and diff use its owner task id and authoritative LAN/cloud transport, including after tear-off; LAN reads do not depend on relay configuration; missing, removed, offline, or unreachable worktrees display an unmistakable unavailable/error state instead of `0 files`, `(empty)`, or local repo contents; truncated remote diffs retain their partial patch and show an unmistakable warning; targeted Rust/TypeScript tests and checks pass; and the UI states have been visually inspected.
