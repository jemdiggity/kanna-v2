# Task e0e28134 — bound remote agent snapshots

## Goal

Make agent-stream cold opens and reconnects safe on poor mobile links by
bounding `agent_snapshot` for clients that opt in, while preserving the exact
legacy wire behavior for clients (including desktop) that do not.

## Measurement

`7a38cc18` identified `agent_snapshot` as producer-unbounded. The daemon journal
is a lifetime-long `Vec<SeqAgentEvent>` with no count or byte cap
(`crates/daemon/src/agent.rs`), and `AttachAgent { from_seq }` clones every
entry from that sequence into one snapshot. KSP currently maps that entire
vector into one `agent_snapshot` (`crates/kanna-server/src/ksp.rs`). Text
payloads are capped individually at 64 KiB, but event count is unlimited; an
ASCII 64 KiB text event serializes to about 64.1 KiB including its event and
sequence envelope, so about 256 such events exceed the relay's 16 MiB
`maxPayload`. A realistic long agent session can contain hundreds or thousands
of assistant, thinking, tool-call, tool-result, and progress events, so total
size grows linearly for the whole session and has no finite worst-case ceiling.
JSON escaping can make the wire representation larger still (up to roughly
6× for escape-heavy text). Moreover, a single event has no finite bound:
`UserMessage.text` is not truncated, and `ToolCall.input` and
`PermissionRequest.input` accept arbitrary JSON; identifiers and several
diagnostic/message fields are also unconstrained by the event schema. The
capability-gated representation must therefore bound an oversized individual
event as well as limiting event count and aggregate bytes.

## Scope and contract

- Add an opt-in KSP capability for a recent, byte-and-count-bounded initial
  agent window. The attachment retains the omitted daemon replay and serves
  bounded chunks on demand over the existing KSP connection.
- The window and chunks preserve sequence numbers and order. Mobile prepends
  older chunks as the agent reader approaches its oldest loaded event.
- Reattach presents the stream client's existing `from_seq`; when it is a
  valid continuation, only missed events are delivered and the client's
  existing window is retained. Reuse the existing agent sequence resume path.
- A client without the capability receives the same `agent_snapshot` frame and
  full journal as before, byte for byte. Desktop does not advertise the new
  capability.
- Wire the capability and history walk through `packages/stream-client` and
  both mobile transports. This is JS-only; do not change mobile
  `runtimeVersion`.

Out of scope: changing daemon journal retention or event semantics, changing
the relay payload limit, and desktop UI behavior.

## Done when

KSP protocol tests cover the bounded snapshot, history request/response,
delta reattach, and unchanged non-advertising behavior; mobile/stream-client
tests cover the backfill trigger and reconnect preservation; relevant Rust and
pnpm test/typecheck suites pass (plus relay tests only if relay code changes).

## Implemented behavior

`agent_history_window` caps the recent snapshot at 200 events and a 512 KiB
frame budget (508 KiB reserved for serialized events, leaving 4 KiB for the
envelope). A single event over that reservation is copied into a bounded wire
representation: arbitrary JSON input is replaced by a truncation marker and
strings are shortened on UTF-8 boundaries until the serialized event fits;
its sequence and event kind are retained. The daemon journal and legacy wire
representation are unchanged. `agent_history_request` /
`agent_history_chunk` walk older events backward in chunks of at most 200
events under the same byte budget. Each request carries an `after_seq` fence:
on reconnect it is the client's previous
`from_seq`, so backfill cannot cross into events already held by the phone.

The shared stream client continues to present its last `next_seq` on attach.
Capability snapshots mark reconnects as `resumed`; mobile merges those events
by sequence and preserves its loaded transcript. If a disconnect gap itself is
larger than the recent window, mobile walks that gap first and then resumes any
older cold-open history walk it had already started. Both LAN and relay mobile
agent streams advertise the capability. Desktop and every other
non-advertising client receive the original full `agent_snapshot` serialization
with all new optional fields omitted.

KSP retains one shared history per daemon session across WebSocket lifetimes
and merges each daemon replay into it instead of replacing it. If that bounded,
process-local history expires or is evicted, the next windowed attach rebuilds
the backfill source from sequence zero of the daemon's durable journal, then
filters the client-facing snapshot at the client's requested nonzero sequence.
Reconnect and internal daemon-reattach snapshots therefore remain delta-only,
while omitted cold-open history remains recoverable independently of cache
retention. Detached histories have a two-minute reconnect grace and a
16-session idle bound; those are optimizations, not durability requirements.
An expired detached history is replaced when that same session next attaches;
it does not require another session to trigger registry pruning. Histories
with another active owner and detached histories still inside the grace are
reused.

Coverage includes KSP bounded-window/backfill, legacy full snapshots, and
sequence-delta reattach; stream-client capability/request/reconnect behavior;
and mobile transport, history-trigger, merge, and reconnect behavior. No relay
code or native mobile configuration changed, so the relay suite and mobile
`runtimeVersion` are unchanged.
