# Task 9e36a8c7: desktop anonymous push identity and pairing certificate

## Goal

Implement phase 2 of `docs/specs/anonymous-push-notifications.md`: have
`kanna-server` create and persist a long-lived Ed25519 anonymous desktop
identity, and issue a desktop-signed, approximately 24-month pairing
certificate that binds each paired mobile device to that identity.

## Scope

- Extend the LAN pairing claim response additively with the desktop push
  identity (public key plus relay environment/URL) and a certificate containing
  `deviceId`, `issuedAt`, `expiresAt`, and the desktop signature.
- Re-issue a fresh certificate to an already-paired device over an authenticated
  LAN path, and persist the returned identity/certificate with the mobile
  pairing session.
- Preserve the shipped compact `KANNA1` QR payload and existing LAN request
  authentication.
- Cover first claim and authenticated re-issue through the real LAN pairing
  ceremony, including signature verification.

Relay registration/authentication, notification delivery behavior, revocation,
and any LAN notification-banner path are deliberately out of scope.

## Constraints and completion

The private key never leaves the desktop and survives normal restarts. Losing
or rotating it invalidates prior certificates; recovery is deliberately by
re-pairing. The mobile change is JS-only and does not bump `runtimeVersion`.
The work is done when server, mobile persistence, compatibility/unit tests, and
real-LAN claim/re-issue E2E coverage pass, with formatting, Clippy, and
TypeScript checks clean for the touched surfaces.
