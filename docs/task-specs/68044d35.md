# Task 68044d35: Firebase Functions deploy packaging

## Goal

Make Firebase Functions deploys include the compiled `dist/src/index.js` entrypoint and fail early with an actionable error if that build artifact is absent.

## Scope and constraints

- Anchor the `src`, `test`, and `scripts` Functions ignore entries in `firebase.json`, with a comment preserving why.
- Empirically determine whether Firebase packaging also needs a nested `.gitignore` exception for `dist/`; keep only the configuration needed while preserving `kd`'s clean-worktree deploy flow.
- Keep the existing single Functions build in `kd`; add no duplicate build.
- Add kd mocked-runner coverage for the artifact guard and a regression check for the anchored ignore entries.
- Do not perform a production deploy or broaden cloud-deploy behavior beyond this packaging failure mode.

## Done when

`./kd cloud deploy --functions --staging` can proceed from a fresh clean worktree after its normal build, the compiled entrypoint is present in the Firebase upload package, missing output fails before deploy with a clear message, and `pnpm --filter @kanna/kd test` plus `pnpm test` pass.

## Packaging decision

Firebase CLI 14.27.0 packaging was exercised directly after the Functions build. The original ignore list produced a 958-byte zip without `dist/src/index.js`; anchoring the three entries alone produced a 106,742-byte zip containing the entrypoint. The packager uses `functions.ignore`, not repository `.gitignore` rules, so no nested `.gitignore` negation is needed and root `dist/` remains ignored to preserve the clean-worktree deploy flow.
