## Done

`KANNA_IOS_SIMULATOR_NAME='iPhone 17 Pro' ./kd test remote-e2e --dev --mobile-relay` reaches and passes the existing task journeys and terminal-keys journey on this machine, with both root causes and fixes recorded here.

## Root causes and fixes

1. PR #1273's windowed KSP terminal protocol intentionally replaced the full initial VT snapshot with a bounded recent window and separately advertised retained scrollback. The scripted fixture still generated 10,050 deterministic history lines, but its precondition measured only the now-bounded `dataB64` field and therefore waited for an impossible 1,000,001 encoded characters. The harness now proves the current contract instead: the initial window is bounded below 100,000 encoded characters, contains the sentinel, and advertises at least 9,000 retained scrollback lines. A live focused run observed 7,356 encoded characters, 5,517 decoded bytes, and 9,987 retained lines. Relaxing the old size assertion is correct because a negotiated mobile client no longer exercises an oversized initial-snapshot path; retaining it through a legacy/unwindowed observer would test a different protocol from the app.
2. The portable cloud ownership work publishes a stable `cloudTaskId` for real server tasks, and mobile deliberately uses that identity ahead of the legacy `cloud:<desktop>:<repo>:<local-task>` fallback. The relay successfully wrote the Firestore task document, but the Appium harness kept looking for the fallback selector and reported the existing row as absent. The publication preflight now returns the row's authoritative `cloudTaskId` (falling back only for legacy documents), and all later task journeys use that id.

## Additional harness drift exposed after setup

- Current task cards include `Task ID <id>` in their accessibility label. The relay assertions now match that intentional label.
- The deterministic ordering rows can put the real task outside the iPhone 17 Pro viewport. Known-row assertions and opens now scroll the exact row into view instead of equating `displayed` with `published`.
- The former Recent tab is now unread-only Activity. The journey explicitly drives the fixture to `unread` for its Activity-row assertion and restores `working` before the existing activity-transition checks.
- The snapshot observer previously accepted the first matching-content attach snapshot and only then compared geometry. Snapshot expectations can now include rows and columns so a geometry assertion waits for the requested state.
- The relay fixture now creates its PTY at the deterministic, authoritative mobile geometry (80x48). A separate product-wiring regression was exposed while doing so: mounting the real mobile detail did not resize an initially 80x24 PTY. No product code was changed here; follow-up task `2462ddd0` owns that investigation.
- The long retained-history fixture's independent terminal observer is a rendered-window observer, not a durable receipt ledger. Its `outputText()` can be replaced by KSP recovery snapshots, and live PTY responses are not guaranteed to remain observable there while the heartbeat advances the bounded window. This caused false negatives first for terminal-key markers and then for submitted-input markers even though server/daemon tracing proved the bytes reached the child. The scripted fixture now appends exact child-read key acknowledgements and NUL-delimited multiline inputs to files in its disposable worktree. Terminal keys, quick reply, and file-preview setup assert those deterministic ledgers; quick reply also asserts exactly one matching durable server `task_input` row.

Product code explicitly attempts the reset, so weakening the existing journey would hide a regression. No product code was changed here; separate task `392e1e6e` owns the fix.
