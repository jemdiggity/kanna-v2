## Done

`KANNA_IOS_SIMULATOR_NAME='iPhone 17 Pro' ./kd test remote-e2e --dev --mobile-relay` reaches and passes the existing task journeys and terminal-keys journey on this machine, with both root causes and fixes recorded here.

## Root causes and fixes

1. PR #1273's windowed KSP terminal protocol intentionally replaced the full initial VT snapshot with a bounded recent window and separately advertised retained scrollback. The scripted fixture still generated 10,050 deterministic history lines, but its precondition measured only the now-bounded `dataB64` field and therefore waited for an impossible 1,000,001 encoded characters. The harness now proves the current contract instead: the initial window is bounded below 100,000 encoded characters, contains the sentinel, and advertises at least 9,000 retained scrollback lines. A live focused run observed 7,356 encoded characters, 5,517 decoded bytes, and 9,987 retained lines. Relaxing the old size assertion is correct because a negotiated mobile client no longer exercises an oversized initial-snapshot path; retaining it through a legacy/unwindowed observer would test a different protocol from the app.
2. The portable cloud ownership work publishes a stable `cloudTaskId` for real server tasks, and mobile deliberately uses that identity ahead of the legacy `cloud:<desktop>:<repo>:<local-task>` fallback. The relay successfully wrote the Firestore task document, but the Appium harness kept looking for the fallback selector and reported the existing row as absent. The publication preflight now returns the row's authoritative `cloudTaskId` (falling back only for legacy documents), and all later task journeys use that id.
