# Task d66c4550 — new-task modal dead-ends on cloud-only repos with no listable base branch

## Problem

On this machine, `kanji-kongbu` appears in the desktop sidebar as a repo
project with only remote tasks: the repo is not registered locally in the
instance's DB, so the cloud task index mints a `cloud:` repo from the owning
desktop's published tasks. Opening the new-task modal for such a repo lists
base branches with `git ls-remote <remote_url>`. When that fails — here the
machine's active GitHub credential (`jeremy-aminiti`) cannot see the private
`jemdiggity/kanji-kongbu` repo, so GitHub answers "Repository not found" — the
error is swallowed into `console.debug`, the branch list stays empty, and the
Create button is permanently disabled (`!hasValidBaseBranch`). The user is
stuck with no explanation and no way forward.

## Goal

Creating a local task for a cloud-only repo must not silently dead-end when
the remote cannot be listed.

## Change

In `useAppTaskCreation.openNewTaskModal`'s cloud-only branch:

- When `git_list_remote_base_branches` fails or yields no candidates, fall
  back to offering `origin/<default_branch>` using the default branch the
  owning desktop published in the cloud snapshot, so the modal stays usable.
  The clone on submit then reports the real error (auth, network) as a toast
  instead of the modal being wedged before the user can act.
- Surface the listing failure itself as an error toast
  (`toasts.remoteBaseBranchesFailed`) instead of only `console.debug`.

## Scope

- In: the modal's cloud-only base-branch loading path, its unit tests, the new
  i18n key (en/ja/ko).
- Out: injecting GitHub credentials into `git ls-remote` / `git clone`
  (the machine's credential setup is the operator's to fix; Kanna's bug is the
  silent dead-end), any change to the local-repo path, and any modal layout
  change.

## Done when

- A cloud-only repo whose remote cannot be listed still opens a usable
  new-task modal with `origin/<published default>` preselected, and the
  listing failure is visible as a toast.
- Unit tests cover the fallback (listing failure, and missing remote URL).
- E2E note recorded for the uncovered wiring (mock harness has no cloud
  snapshot fixture): `docs/2026-08-30-cloud-only-base-branch-fallback-e2e-gap.md`.
