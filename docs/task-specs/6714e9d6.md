# Task 6714e9d6: reliable mobile repo-command task loading

## Goal

After a mobile repository command creates a task, load that task from the desktop that actually ran the command, tolerating a brief creation/read race.

## Scope and constraints

- Trace and fix the More-tab command launch-to-task-load flow and its server/API contract where necessary.
- On a successful launch followed by a load failure, clearly say the task was created and direct the user to Tasks; do not imply the command failed.
- Cover success, post-launch load failure, and two paired desktops exposing the same repository under different identities.
- Add server contract tests if the response changes, and real-server E2E coverage when practical; otherwise update or add a dated E2E-gap note.
- Keep the change JS-only if possible; do not bump the mobile runtime version unless native code or configuration must change.
- Do not refactor unrelated command, repository, or task routing behavior.

## Done when

The launch response provides an unambiguous task owner, mobile uses it for bounded post-launch retries, failure copy accurately preserves successful creation, and focused tests and required checks pass.
